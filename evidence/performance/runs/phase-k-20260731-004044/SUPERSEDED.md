# Phase K performance run — SUPERSEDED

The Phase K performance run at `evidence/performance/runs/phase-k-20260731-004044/`
is **superseded** (residual L1-S).  It is retained in full — raw Criterion

rewritten.

## Reasons for invalidation

The run's exported metadata does not meet the project's evidence doctrine
(see `evidence/phase-l/gap-ledger.md` L1-A..L1-S):

1. **Fabricated sample counts**: all 831 records report `sample_count = 1`
   (the exporter defaulted a missing value; Criterion's actual samples live
   in `sample.json`).
2. **Hardcoded verification**: all 831 records report
   `verification_passed = true` and `status = "pass"` without any preflight
   evidence channel.
3. **Empty hashes**: no `output_hash`, words-consumed hash, or final-state
   hash.
4. **Unknown identity fields**: `profile = "unknown"`, `api = "unknown"`,
   1/1 threads on every record — identity was derived from sanitized
   directory names, not Criterion's `benchmark.json`.
5. **Zero throughput fields**: 798 of 831 records report `bytes = 0` and
   `throughput_gib_s = 0`.
6. **Truncated archive paths**: the custom tar writer truncated names at
   99 bytes, including truncated `.json` extensions.
7. **Wrong index hash semantics**: the index `sha256` was the canonical
   self-hash with an empty self-hash field, not the final receipt file hash.
8. **No parity citations**: the parity model still reported
   `performance_status: "unsealed"` and cited no performance receipts.
9. **No main-seal integration**: `cargo xtask seal` did not validate
   performance evidence.
10. **Seal-time provenance**: host metadata, RUSTFLAGS, and Git state were
    captured at sealing time, not at benchmark time; the run could not be
    bound to the code that produced it.

## Status

`superseded` — a new valid run is generated by Phase L.18 through
