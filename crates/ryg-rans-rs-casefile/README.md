## What This Crate Is

This crate defines the **data model** for the ryg-rans-rs forensic evidence system.
The types in this crate are the foundation of the project's **court-of-record**
architecture — every algorithmic surface is verified by cross-decoding courts that
produce receipts and manifests serialized using these types.

This crate is `#![no_std]` + `#![forbid(unsafe_code)]`. It depends only on `serde`
and `sha2`. It has **zero knowledge of rANS arithmetic, SIMD, or any other
implementation detail**. It is a pure data model crate, usable independently by
downstream consumers, security auditors, and researchers who need to parse and
verify evidence artifacts.

### What It Is Not

This crate does **not** contain:

- Any rANS encoding or decoding logic
- Any oracle or court orchestration code
- Any SIMD intrinsics or unsafe code
- Any I/O or file system operations

It is purely a **schema definition** crate.

---

## Why a Separate Schema Crate

1. **Independent verification**: Downstream consumers, security auditors, and researchers
   can parse and verify evidence artifacts without depending on the full oracle harness
   or the rANS algorithmic crates.

2. **Schema stability**: The types are frozen at schema version 1. Changing a field name
   or adding a variant is a breaking change that requires a schema version bump. This
   stability is critical for the evidence system — receipts generated by version 0.1.6
   are still parseable by version 0.1.27.

3. **No rANS dependency**: This crate has no dependency on any rANS crate. It only depends
   on `serde` for serialization and `sha2` for hash computation. This means auditors
   can verify evidence without needing to trust any rANS implementation.

4. **Separation of concerns**: The evidence schema is a cross-cutting concern that spans
   oracle generation, sealing verification, and downstream consumption. Isolating it
   prevents circular dependencies and keeps the schema stable.

## Core Types

### `Casefile` — A Single Deterministic Test Case

```rust
/// A single deterministic test case for cross-decoding verification.
pub struct Casefile {
    /// Schema version — always 1 for the current format.
    pub schema_version: u32,

    /// Unique case identifier.
    ///
    /// Format: `RYG_RANS.<SURFACE>.<PROFILE>.S<SCALE_BITS>.<NUM>`
    /// Example: `RYG_RANS.AVX512VL.INTERLEAVED8.UNIFORM256.S12.0000`
    pub case_id: &'static str,

    /// Pinned upstream C commit hash defining the reference behavior.
    pub upstream_commit: &'static str,

    /// Algorithmic variant identifier.
    ///
    /// Examples: `"byte32"`, `"r64"`, `"word"`, `"avx512vl-interleaved8"`
    pub variant: &'static str,

    /// Operation being tested.
    ///
    /// Examples: `"encode_decode"`, `"encode_only"`, `"decode_only"`
    pub operation: &'static str,

    /// PRNG seed for deterministic input generation.
    pub seed: u64,

    /// SHA-256 hash of the input data (optional).
    pub input_sha256: Option<[u8; 32]>,

    /// The input byte stream to encode.
    pub input: Vec<u8>,

    /// Entropy scale (14 for byte rANS, 12 for word rANS).
    pub scale_bits: u32,

    /// Per-symbol frequencies (256 entries for byte alphabet).
    pub frequencies: Vec<u32>,

    /// Cumulative frequencies (257 entries — cum[0]=0, cum[256]=total).
    pub cumulative_frequencies: Vec<u32>,

    /// Interleave factor: 1, 2, 8, or 16 lanes.
    pub interleave: u32,
}
```

A `Casefile` contains everything needed to reproduce a specific test: the input data,
the frequency model, the scale bits, the interleave factor, and the upstream commit
that defines the reference behavior.

**Validation invariants** (not enforced by the type system, but guaranteed by construction
in the oracle):

1. `frequencies.len() == 256`
2. `cumulative_frequencies.len() == 257`
3. `cumulative_frequencies[0] == 0`
4. `cumulative_frequencies[256] == 1 << scale_bits`
5. `cumulative_frequencies[i] >= cumulative_frequencies[i-1]` for all `i`
6. `scale_bits` is valid for the variant (12 for word rANS, 14 for byte rANS)
7. `interleave` is 1, 2, 8, or 16

### `Receipt` — Court Verdict

```rust
/// A court verdict for one algorithmic surface.
pub struct Receipt {
    /// Schema version — always 1.
    pub schema_version: u32,

    /// Court identifier — the algorithmic surface being verified.
    ///
    /// Example: `"RYG_RANS.AVX512VL.INTERLEAVED8.UNIFORM256.S12"`
    pub court_id: &'static str,

    /// Number of cases in this court (typically 8).
    pub case_count: u32,

    /// Primary pass/fail verdict.
    ///
    /// - `"admitted_match"`: Every comparison passed.
    /// - `"admitted_partial"`: Some comparisons failed; residuals exist.
    pub verdict: &'static str,

    /// Pinned upstream C commit hash (c9d162d9...).
    pub upstream_commit: &'static str,

    /// Git commit of the Rust implementation (optional).
    pub rust_commit: Option<&'static str>,

    /// Total number of comparisons made across all cases.
    pub pairs_compared: u64,

    /// Number of comparisons that matched.
    pub pairs_matched: u64,

    /// Number of residuals (documented differences).
    pub residual_count: u32,

    /// Links to residual records for each failure.
    pub residual_ids: Vec<&'static str>,

    /// Unix timestamp of evidence generation (optional).
    pub timestamp: Option<u64>,
}
```

The `verdict` field is the primary pass/fail indicator:

- **`admitted_match`**: Every comparison passed. The Rust implementation matches the
  upstream C oracle exactly, on every case, for every check. The surface can be
  marked as fully verified.

- **`admitted_partial`**: Some comparisons failed. Residuals exist. The surface cannot
  be marked `full` until all residuals are resolved. This verdict triggers investigation.

**SHA-256 self-hash**: The `receipt.receipt_sha256` is computed when creating the
receipt — it is the SHA-256 of the receipt JSON **without** the `receipt_sha256` field.
This self-authenticating design prevents forgery.

### `Residual` — A Documented Difference

```rust
/// A documented difference between Rust and C oracle implementations.
///
/// Residuals are NEVER deleted — even after resolution, the record remains
/// with status: "fixed" for auditability.
pub struct Residual {
    /// Case ID where the difference was observed.
    pub case_id: &'static str,

    /// Court ID for the algorithmic surface.
    pub court_id: &'static str,

    /// Algorithmic variant (e.g., "avx512vl-interleaved8").
    pub variant: &'static str,

    /// Pinned upstream C commit hash.
    pub upstream_commit: &'static str,

    /// Classification of the residual.
    ///
    /// - `"implementation"`: Bug in the Rust implementation
    /// - `"oracle"`: Bug or limitation in the C oracle
    /// - `"casefile"`: Error in the test case definition
    /// - `"design"`: Intentional design difference (documented and accepted)
    pub class: &'static str,

    /// Severity level.
    ///
    /// - `"S0"`: Critical — incorrect decode results
    /// - `"S1"`: Significant — divergence in edge cases
    /// - `"S2"`: Minor — cosmetic or performance difference
    /// - `"S3"`: Informational — not a bug, but worth documenting
    pub severity: &'static str,

    /// Resolution status.
    ///
    /// - `"open"`: Not yet investigated
    /// - `"investigating"`: Actively being analyzed
    /// - `"fixed"`: Resolved; residual remains for audit trail
    /// - `"wontfix"`: Accepted as intentional or out of scope
    pub status: &'static str,
}
```

Residuals are **never deleted** — even after resolution, the record remains with
`status: "fixed"` for auditability. This ensures a complete audit trail of all
differences discovered during the project's history.

**Display implementation**:

```rust
impl Display for Residual {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(
            f,
            "{} ({}): {} [{}] - {}",
            self.case_id, self.variant, self.class, self.severity, self.status
        )
    }
}
```

Example output:
```
RYG_RANS.BYTE.DIVISION.UNIFORM256.S14.0000 (byte32): implementation [S1] - fixed
```

## Evidence SHA-256 Chain

The evidence system uses a three-level hash chain to guarantee integrity:

```text
evidence/index.json
  └── contains sha256_of(receipt.json) for every receipt
        └── receipt.json contains sha256_of(manifest.json)
              └── manifest.json contains all case data

Self-hash: receipt.json.receipt_sha256 == sha256(receipt.json without receipt_sha256)
```

### Level 1: Index (`index.json`)

```json
{
  "schema_version": 1,
  "run_id": "2025-01-15T10:30:00Z",
  "receipt_count": 144,
  "receipts": {
    "RYG_RANS.BYTE.DIVISION.UNIFORM256.S14": {
      "sha256": "abcd1234...",
      "path": "receipts/RYG_RANS.BYTE.DIVISION.UNIFORM256.S14.json"
    },
    ...
  },
  "index_sha256": "efab5678..."
}
```

The index maps each receipt to its SHA-256 hash. Any modification to a receipt changes
its hash, which is detected by the index.

### Level 2: Receipt

```json
{
  "schema_version": 1,
  "court_id": "RYG_RANS.AVX512VL.INTERLEAVED8.UNIFORM256.S12",
  "case_count": 8,
  "verdict": "admitted_match",
  "upstream_commit": "c9d162d996fd600315af9ae8eb89d832576cb32d",
  "rust_commit": "a1b2c3d4e5f6...",
  "pairs_compared": 64,
  "pairs_matched": 64,
  "residual_count": 0,
  "residual_ids": [],
  "timestamp": 1736939400,
  "receipt_sha256": "abcd1234...",
  "manifest_sha256": "efab5678..."
}
```

### Level 3: Manifest

```json
{
  "schema_version": 1,
  "court_id": "RYG_RANS.AVX512VL.INTERLEAVED8.UNIFORM256.S12",
  "cases": [
    {
      "case_id": "RYG_RANS.AVX512VL.INTERLEAVED8.UNIFORM256.S12.0000",
      "seed": 42,
      "scale_bits": 12,
      "interleave": 8,
      "profile": "UNIFORM256",
      "checks": [
        { "id": "c_self_decode", "passed": true },
        { "id": "rust_scalar_self_decode", "passed": true },
        { "id": "rust_simd_self_decode", "passed": true },
        { "id": "compressed_match", "passed": true },
        { "id": "c_to_rust_scalar", "passed": true },
        { "id": "c_to_rust_simd", "passed": true },
        { "id": "rust_to_c", "passed": true },
        { "id": "simd_scalar_agree", "passed": true }
      ],
      "backend": "avx512vl-8way",
      "backend_assertion_passed": true
    }
  ],
  "summary": {
    "total_cases": 8,
    "passed": 8,
    "failed": 0,
    "backend_assertions_passed": 8
  }
}
```

### Security Properties

1. **No receipt can be modified** without changing its hash in the index
2. **No manifest can be modified** without changing its hash in the receipt
3. **No receipt can be forged** without recomputing the self-hash (which requires
   knowing the exact serialization format)
4. **The evidence directory is self-authenticating** — the index's integrity is
   verified by the `xtask seal` command

## Full Schema Documentation

### Field Reference: `Casefile`

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `schema_version` | `u32` | Must be `1` | Identifies the schema version |
| `case_id` | `&str` | Pattern: `RYG_RANS\.[A-Z0-9._]+\.[0-9]{4}` | Globally unique case ID |
| `upstream_commit` | `&str` | 40 hex chars | Upstream C commit hash |
| `variant` | `&str` | One of defined variants | Algorithmic variant |
| `operation` | `&str` | `encode_decode`, `encode_only`, `decode_only` | What is being tested |
| `seed` | `u64` | Any | PRNG seed |
| `input_sha256` | `Option<[u8; 32]>` | 32 bytes | Optional input hash |
| `input` | `Vec<u8>` | Any | Input data |
| `scale_bits` | `u32` | 1..=31 (variant-dependent) | Entropy scale |
| `frequencies` | `Vec<u32>` | len=256, sum=1<<scale_bits | Symbol frequencies |
| `cumulative_frequencies` | `Vec<u32>` | len=257, monotonic | Cumulative frequencies |
| `interleave` | `u32` | 1, 2, 8, or 16 | Interleave lanes |

### Field Reference: `Receipt`

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `schema_version` | `u32` | Must be `1` | Schema version |
| `court_id` | `&str` | Pattern: `RYG_RANS\.[A-Z0-9._]+` | Court surface ID |
| `case_count` | `u32` | > 0 | Number of cases |
| `verdict` | `&str` | `admitted_match` or `admitted_partial` | Pass/fail |
| `upstream_commit` | `&str` | 40 hex chars | C commit hash |
| `rust_commit` | `Option<&str>` | 40 hex chars | Rust commit hash |
| `pairs_compared` | `u64` | ≥ 0 | Total comparisons |
| `pairs_matched` | `u64` | ≤ pairs_compared | Matching comparisons |
| `residual_count` | `u32` | ≥ 0 | Number of residuals |
| `residual_ids` | `Vec<&str>` | len = residual_count | Residual references |
| `timestamp` | `Option<u64>` | Unix timestamp | Generation time |

### Field Reference: `Residual`

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `case_id` | `&str` | Must reference existing case | Originating case |
| `court_id` | `&str` | Must reference existing court | Court surface |
| `variant` | `&str` | One of defined variants | Algorithmic variant |
| `upstream_commit` | `&str` | 40 hex chars | C commit hash |
| `class` | `&str` | `implementation`, `oracle`, `casefile`, `design` | Classification |
| `severity` | `&str` | `S0`, `S1`, `S2`, `S3` | Severity level |
| `status` | `&str` | `open`, `investigating`, `fixed`, `wontfix` | Resolution status |

## Serialization Format

All types are serialized as JSON via `serde` with the following conventions:

| Rust Type | JSON Type | Notes |
|-----------|-----------|-------|
| `u32` | number | Integer |
| `u64` | number | Integer |
| `Vec<u8>` | string (hex) | Lowercase hex-encoded |
| `[u8; 32]` | string (hex) | Lowercase hex-encoded |
| `Option<T>` | T or null | Omitted when null |
| `&str` | string | UTF-8 string |

## Usage

```rust
use ryg_rans_rs_casefile::*;

let case = Casefile::new(
    "RYG_RANS.AVX512VL.INTERLEAVED8.UNIFORM256.S12.0000",
    "avx512vl-interleaved8",
);
case.seed = 42;
case.scale_bits = 12;

let residual = Residual {
    case_id: "...",
    court_id: "RYG_RANS.AVX512VL.INTERLEAVED8.UNIFORM256.S12",
    variant: "avx512vl-interleaved8",
    upstream_commit: "c9d162d996fd600315af9ae8eb89d832576cb32d",
    class: "implementation",
    severity: "S1",
    status: "fixed",
};
println!("{}", residual);
// Output: "... (avx512vl-interleaved8): implementation [S1] - fixed"
```

### Deserializing (by downstream auditors)

```rust

let json = fs::read_to_string("evidence/receipts/AVX512VL.INTERLEAVED8.json").unwrap();

assert_eq!(receipt.verdict, "admitted_match");
assert_eq!(receipt.residual_count, 0);
```
