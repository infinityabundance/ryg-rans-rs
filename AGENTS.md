## Frozen invariants (do not break)

* Bit-exact output parity with the pinned upstream `ryg_rans` revision:
  any change that alters an encoded stream is a breaking format change and
  invalidates every receipt.
* Determinism: same input → same output and same canonical error,
  independent of worker count, completion order, or schedule.
* Strict integrity is the default: zero/unset decoded hashes fail.
* Cancellation can never return `Ok` with fewer blocks than declared.
* Explicit backend requests execute exactly or return a typed error.
* `ParallelConfig` has no inert public field; every field has a production
  read site and an observable test.
* Residuals are never deleted; they are resolved or accepted.

## Files that must not be edited by hand

* `evidence/**` — generated by the xtask seal machinery; hand-edits break
  the hashes and the seal gate will (correctly) reject them.
* `Cargo.lock` — managed by cargo.
* `docs/public-api/*.txt` — generated by `cargo public-api`.
* `crates/ryg-rans-rs-simd/unsafe-ledger.toml` — must match the source
  inventory; change the source and regenerate/update the ledger together
  (the bidirectional test enforces equality).
* Raw Criterion trees under `evidence/**/criterion/` — archived as-is.

## Stale-document warning

Prose is not proof.  A claim in any README or doc is true only when it can
be traced through code → test → court → receipt → seal.  If you find a
documentation/code contradiction, treat it as a defect: fix the code or fix
the doc, and record a residual in `evidence/phase-l/gap-ledger.md`.

## Exact test commands

```sh
cargo test --workspace                        # default features
RUSTFLAGS="-C target-cpu=native" cargo test --workspace   # native SIMD
cargo check --workspace --all-targets
cd fuzz && cargo check --workspace            # standalone fuzz workspace
cargo test -p ryg-rans-rs-simd --test unsafe_ledger
cargo test -p ryg-rans-rs-simd --test disasm_court
# Loom concurrency courts (real interleaving exploration of the executor;
# LOOM_MAX_PREEMPTIONS bounds the exponential state space):
LOOM_MAX_PREEMPTIONS=2 RUSTFLAGS="--cfg loom" cargo test -p ryg-rans-rs-parallel --features loom --release --test loom_tests
LOOM_MAX_PREEMPTIONS=2 RUSTFLAGS="--cfg loom" cargo test -p ryg-rans-rs-parallel --features loom --release --lib -- loom_channel
```

## Evidence-generation commands

```sh
cargo xtask benchmark-run --criterion-dir target/criterion ...
cargo xtask performance-seal ...
cargo xtask seal
```

See `xtask/README.md`.  The seal gate is the single authoritative final
gate (L.20): it must pass fully before any "Sealed" claim is made.

## Unsafe-code rules

* Every `unsafe fn` carries its own exact `#[target_feature]` attributes;
  callers must not be relied on for target features.
* Every `unsafe fn` has a `# Safety` section stating pointer provenance,
  bounds, alignment, CPU-feature requirements, and caller list.
* No hidden caller obligation may exist that could be encoded in a safe
  type.
* The ledger test (`unsafe_ledger.rs`) fails if the ledger and the source
  inventory disagree.

## Backend naming glossary

`scalar` · `sse41-8way` · `avx2-manual-gather` · `avx2-hardware-gather` ·
`avx2-2x8` · `avx2-uniform256` · `avx2-batch4` · `avx512vl-8way` ·
`avx512-16way`.  `requested` and `executed` are always recorded separately.

## Current limitations (as of Phase L.18, implementation commit 8401991)

* CLI `encode` implements codecs byte-single, byte-interleaved2,
  r64-single, word-single; other codecs return a typed unsupported error
  (exit 6).  CLI `trace` supports byte-single blocks only.
* CLI `decode` supports codecs 1, 2, 3, 5 and 7 (8-way via SIMD/scalar);
  codecs 4, 6, 8, 9, 10 return typed unsupported errors.
* CLI cancellation is cooperative and block-granular: SIGINT/SIGTERM
  (Unix, optional `signals` feature, on by default) and `--timeout N`
  (fractional seconds) return the typed `Cancelled` error with exit code 11
  at the next block boundary; the CLI does not asynchronously interrupt a
  single in-flight block.
* The `bench` subcommand is a live smoke measurement; the Criterion suite
  is the sealed measurement surface.
* Performance evidence is re-sealed in Phase L.18 at implementation commit
  `8401991` (run `phase-l-20260802a`, 800 cases × 100 samples); the Phase K
  run is superseded (see `evidence/performance/superseded/`).

## How to verify claims rather than trusting prose

1. Find the claim in the README.
2. Find the producing code path.
3. Find the test/court that pins it.
4. Find the receipt in `evidence/`.
5. Run the seal gate.
If any link is missing, the claim is not sealed and must not say "Sealed".
