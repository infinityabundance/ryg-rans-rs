# Paper 0003 — The SIMD decode kernels

> *Layer: Algorithm/Subsystem.  Companion: `docs/papers/0002-word-rans.md`
> (the packed table), `docs/unsafe-ledger.md` (the safety contracts),
> `docs/bitstream-contract.md`.  Code: `crates/ryg-rans-rs-simd/`.
> Every kernel below has a scalar reference, differential tests,
> report-parity courts, disassembly courts, and a ledgered unsafe surface.*

## 1. The dispatch philosophy

The SIMD crate exposes **safe wrapper functions** for every kernel.  A
caller cannot invoke an intrinsic path without runtime feature detection;
each `_checked` wrapper verifies the CPU supports the required ISA before
entering the `unsafe` kernel, and returns `DecodeError::UnsupportedBackend`
(a typed error) when it does not.  There is no silent fallback: the wrapper
does not "try SSE4.1, fall back to scalar" behind the caller's back — the
caller chooses the backend, and the wrapper either executes it exactly or
reports that it cannot.

The parallel engine's planner (`crates/ryg-rans-rs-parallel/src/decode_plan.rs`)
is deliberately **capability-agnostic**: it validates format compatibility
(8-way ↔ codec 7, 16-way ↔ codec 8, Uniform256 ↔ validated model, batch ↔
coordinator context) and produces the exact requested plan or a typed
error.  Execution capability is checked at execution time by the kernel's
own wrapper.  This separation means the planner never needs to know the
host CPU, and the executor never needs to re-derive format rules.

## 2. The backend matrix

| Backend | ISA | Width | Gather | Table | Stream |
|---------|-----|-------|--------|-------|--------|
| `Scalar8` / `Scalar16` | baseline x86-64 (or portable) | 8/16 | — | packed | codec 7 / 8 |
| `Sse41Interleaved8` | SSE4.1 | 8 | `pshufb`-based / scalar gather | unpacked `RansWordTables` | codec 7 |
| `Avx2ManualGather8` | AVX2 | 8 | manual (per-lane loads) | packed | codec 7 |
| `Avx2HardwareGather8` | AVX2 | 8 | `vpgatherdd` | packed | codec 7 |
| `Avx2TwoBy8On16` | AVX2 | 16 (2×8) | manual | packed | codec 8 |
| `Avx2Uniform256TableFree16` | AVX2 | 16 | none (arithmetic) | none | codec 8, Uniform256 |
| `Avx512VlInterleaved8` | AVX-512VL | 8 | `vpgatherdd` | packed | codec 7 |
| `Avx512VlManualGather8` | AVX-512VL | 8 | manual | packed | codec 7 |
| `Avx512Interleaved16` | AVX-512 | 16 | `vpgatherdd` | packed | codec 8 |
| `Avx512ManualGather16` | AVX-512 | 16 | manual | packed | codec 8 |
| `Avx512Vl2x8` | AVX-512VL | 16 (2×8) | manual | packed | codec 8 |
| `Avx512Batch4` | AVX-512 | 4 blocks × 16 | packed | codec 8 | coordinator batch |

The two "gather families" exist because hardware gathers (`vpgatherdd`)
have historically had high latency and unpredictable throughput on some
microarchitectures, while manual gathers (four sequential loads into a
vector) have predictable throughput.  The repository implements both and
lets the planner/benchmark decide; the report-parity courts require both to
produce identical results.

## 3. What each kernel does, and why it exists

### 3.1 SSE4.1 8-way (`rans_word_sse41.h` heritage)

The upstream kernel: 8 lanes, each with a 32-bit state; per output byte the
lane computes `slot = state & 0xfff`, looks up `slot2sym` and the slot
entry, and advances the state.  The upstream uses `pshufb`-style shuffles
for the table lookups; this repository's reconstruction uses the unpacked
`RansWordTables` and implements the same arithmetic with the same stream
format.  It is the compatibility surface: the receipts
`RYG_RANS.SIMD.INTERLEAVED8.*` prove byte-exact cross-decoding with upstream.

### 3.2 AVX2 family

* **Manual gather 8**: loads the 8 slot entries with 8 sequential vector
  loads (SIMD-friendly addressing), no gather instruction.  Predictable,
  portable to any AVX2 CPU.
* **Hardware gather 8**: one `vpgatherdd` per step.  Fewer instructions;
  relies on the CPU's gather unit.
* **2×8 on 16**: decodes a 16-way stream using two 8-wide passes —
  important because it allows 16-way streams on AVX2 (which has no 16-lane
  u32 vector).
* **Uniform256 table-free**: for a validated Uniform256 model (every
  frequency exactly 16 at scale 12) the decode reduces to pure arithmetic:
  `sym = slot >> 4`, `next = 16 * (x >> 12) + (slot & 15)` — no table, no
  gather.  This is the "table-free" family; it is also implemented as a
  scalar kernel (`Uniform256TableFree16`) so the parallel engine can select
  it without SIMD.

### 3.3 AVX-512 family

* **VL 8-way**: 256-bit registers, 8 u32 lanes.
* **16-way**: 512-bit registers, 16 u32 lanes — the widest kernel.
* **Manual gather variants**: for microarchitectures where gathers are slow.
* **2×8 on 16 (VL)**: two 8-lane passes for 16-way streams.
* **Batch4**: processes four compatible blocks together (coordinator-level
  grouping); not available through the one-block API by design (Phase L.9:
  `BackendRequiresBatchContext`).

## 4. Microarchitecture discussion

The kernels are written to expose memory-level parallelism: K independent
state registers mean K independent gather addresses per step, which the
out-of-order core can issue in parallel.  The packed 16 KiB table is L1
resident.  The critical instruction mix per step:

* `vpand` (slot mask) — 1 uop;
* gather/loads — K uops of memory traffic;
* `vpmuludq`/`vpsrlq` (quotient + advance) — a few ALU uops;
* renorm compare + conditional word load — branch-free via masks where
  possible.

The main documented limitation: **inactive lanes must not read input**.
In a masked or tail step, lanes beyond the block length must not perform
the word-load that renormalization would perform, because the payload may
end exactly at the block boundary; reading past it is an over-read.  The
kernels implement this with explicit lane masks and the fuzz targets
truncate at every word to prove no over-read.

## 5. The unsafe surface and why it is small

Each kernel is an `unsafe fn` with its own exact `#[target_feature]`
attributes (never inherited from the caller), a complete `# Safety`
section (pointer provenance, bounds, alignment, CPU-feature requirements,
caller list), and a ledger entry (`unsafe-ledger.toml`).  The bidirectional
ledger test fails if the ledger and the source inventory disagree.  The
disassembly courts compile the crate with `-C target-cpu=native` and
verify the expected instructions (`pshufb`, `pblendvb`, `vpermd`,
`vpgatherdd`, `vpmovdb`, …) are present — proving the compiler did not
silently scalarize a kernel.

The unsafe is confined to:

1. intrinsic dispatch (`core::arch::x86_64::*`), which requires
   `#[target_feature]` + unsafe;
2. raw-pointer table access inside the gather kernels, where the safety
   argument is "the table is 4096 entries, the index is `& 0xfff`, and the
   pointer is derived from a `&[PackedWordEntry]` slice whose length is
   checked at construction."

## 6. Performance and the honest reading

The sealed numbers (run `phase-l-20260802b`) show the expected hierarchy
on Zen 5: scalar < SSE4.1 < AVX2 < AVX-512 for throughput, with manual and
hardware gathers within a few percent of each other on this host (the
comparative court and the L.17 analysis discuss why gather choice is
microarchitecture-dependent).  Two honesty rules apply to every SIMD
number in this repository:

1. A benchmark measures **this** kernel, **this** host, **this** build
   (`RUSTFLAGS=-C target-cpu=native`).  Portable builds run the scalar
   reference; the numbers do not transfer.
2. No kernel claims superiority over another implementation with different
   integrity work.  The parallel engine's measured overhead is dominated by
   the mandatory dual SHA-256 per block, not by the kernels (paper 0005).

## 7. Failure modes

1. **Masked over-read** — an inactive lane performing a renormalization
   load past the payload end.  Prevented by lane masks; fuzzed by
   truncation at every word; audited in the `# Safety` sections.
2. **Wrong stream format** — an 8-way kernel running on a 16-way stream (or
   vice versa) produces garbage.  Prevented by the planner's format
   compatibility matrix; the backend courts pin the rejections.
3. **Feature misreport** — the safe wrapper dispatching to a kernel the CPU
   cannot run.  Prevented by `is_x86_feature_detected!` + the runtime
   feature report in the benchmark preflight records.
4. **Compiler scalarization** — a kernel accidentally lowered to scalar
   loads.  Detected by the disassembly courts.
5. **Report divergence** — a kernel producing different words-consumed /
   final-states than its scalar reference.  Detected by the report-parity
   courts (every executable backend must agree).

## 8. Dispatch, runtime detection, and build features

Three feature sources are kept distinct everywhere (Phase L.1-I doctrine):

* `runtime_cpu_features` — what the host CPU supports, from
  `is_x86_feature_detected!` and `/proc/cpuinfo`;
* `compiled_benchmark_features` — what the build targeted, from rustc build
  metadata / `cfg!(target_feature)`;
* `executed_backend_features` — what kernel actually ran, from the
  execution result.

The safe wrappers check runtime features; the planner checks format
compatibility; the benchmark preflight records all three separately.  A
build without `sse4.1`/`avx2`/`avx512` compiled in simply cannot select
those kernels (they are `#[cfg(target_feature)]`-gated), and the safe
wrapper returns `BackendUnavailable` rather than pretending.
