# Model Cache — Performance and Correctness Report (Phase O.19)

Status: **measured** (numbers below are release-mode measurements on the
development host at the Phase O implementation commit; the sealed Criterion
numbers live in the `RYG_RANS.PERF.CACHE.*` receipts generated by
`cargo xtask performance-seal`).

This report separates **static guarantees** (true by construction, pinned
by courts) from **measured findings** (true on this host, pinned by
receipts).  Every workload class is reported separately; nothing is
averaged across incompatible classes, and negative results are reported
with the same weight as positive ones.

---

## 1. Static guarantees

These hold for every configuration, every input, every thread count; they
are proven by the Phase O behavioural courts and the unit/property/loom
suites, not by measurement:

| Guarantee | Proof |
|---|---|
| `current_entries == number of retained entries` | exact per-entry accounting; `invariant_check` recomputes the sum over `retained_entries()` (O.1) |
| `current_bytes == sum of per-entry accounted sizes` | same; mixed-size unit tests + shadow-model proptest (O.1) |
| `current_entries <= max_entries` and `current_bytes <= max_total_bytes` after every public operation | two-phase insert plans the eviction set before mutating; checked arithmetic (O.1) |
| `max_entries == 0` or `max_total_bytes == 0` ⇒ cache disabled | `RejectedDisabled`, nothing retained, decode served by direct construction (O.2) |
| `entry_bytes > max_total_bytes` ⇒ never retained, **and nothing useful is evicted to find out** | `RejectedOversized` with no eviction; the artifact is still delivered for the current decode (O.2) |
| one retained entry per key; same key never occupies two slots | `HashMap` keyed by `ModelCacheKey` + FIFO queue in set equality; replacement removes first (O.3) |
| N concurrent same-key cold requests ⇒ exactly one construction | per-key `Building` marker + condvar single-flight; loom courts (O.5) |
| same-key single-flight survives waiter cancellation + a later arrival | only the builder may remove the in-flight marker (RACE.3, fixed `4389d9b`): a cancelled waiter decrements the diagnostic count but never deletes the RUNNING builder's marker; three-party test + loom court (`loom_cache_cancelled_waiter_keeps_builder_marker`) |
| no abandoned `Building` state possible | builder panic caught → `Panicked`, marker removed, waiters released (O.5) |
| cache failure never reported as a model error | `ModelCacheError::Synchronization` → `uncached_fallbacks` + direct construction with the same canonical constructor (O.6) |
| cached and cache-disabled decode produce identical outputs and semantic errors | both paths call `build_validated_model_artifacts` (O.7) |
| packed tables are actually shared on hit | `Arc<PackedWordTable>` in `ValidatedModelArtifacts`; `Arc::ptr_eq` tests (O.7) |
| metrics invariants: `hits + misses == lookups` (Design A); `builds_completed + build_failures <= builds_started` | O.8 invariant checks; METRICS.2 (fixed `4389d9b`): a lookup whose initial check finds no artifact is a miss — builder, coalesced waiter, and cancelled waiter alike — so the sum holds under cancellation |

The exact byte/entry bound proofs: insertion is planned against the
retained set before any mutation; every arithmetic step is `checked_*`;
the retained-byte sum is recomputed from per-entry sizes by an independent
verifier (`invariant_check`, the proptest shadow model, and the courts) and
compared to the counter.  A violation is a typed `AccountingInvariant`
error that self-heals by clearing the cache and bypassing — decode
semantics are preserved.

## 2. Measured findings

All measurements below: release build, 8 workers unless noted, this host
(16 logical CPUs).  The allocation and contention harnesses are
reproducible: `cargo run --release -p ryg-rans-rs-bench --bin
model_cache_alloc` and `... --bin model_cache_contention`.

### 2.1 Allocation effects (O.15)

Per-decode deltas (allocations / allocated bytes), 32 blocks except where
noted (block counts: ≤256 KiB → 32, hot-set ≥ 16, thrash ≥ 18):

| Mode | 4 KiB | 16 KiB | 64 KiB | 256 KiB | Builds | Peak entries | Peak bytes |
|---|---|---|---|---|---|---|---|
| disabled | 414 / 960 KB | 417 / 1.59 MB | 413 / 4.11 MB | 409 / 14.2 MB | 0 | 0 | 0 |
| cold | 219 / 384 KB | 225 / 1.01 MB | 225 / 3.53 MB | 232 / 13.6 MB | 1 | 1 | 17,472 |
| warm | 219 / 362 KB | 217 / 992 KB | 219 / 3.51 MB | 219 / 13.6 MB | 0 | 1 | 17,472 |
| hot-set | 322 / 669 KB | 321 / 1.30 MB | 327 / 3.81 MB | 330 / 13.9 MB | 16 | 16 | 279,552 |
| thrash | 325 / 686 KB | 326 / 1.31 MB | 333 / 3.83 MB | 333 / 13.9 MB | 17 | 16 | 279,552 |
| unique | 426 / 971 KB | 423 / 1.60 MB | 426 / 4.12 MB | 417 / 14.2 MB | 32 | 32 | 559,104 |

Readings:

* The cache **reduces allocations** when models repeat: cold vs disabled at
  4 KiB is 219 vs 414 allocations (−47%) with one shared artifact; warm is
  even lower (219 vs 414) because no artifact is ever built inside the
  timed region.
* **Packed-table constructions** (the expensive artifact) follow the
  builds column exactly: 1 for cold, 0 for warm, 16 for hot-set, 17 for
  thrash (the 18th insertion evicts the oldest — 1 eviction), 32 for
  unique.  The count is instrumented (`builds_started`), never inferred.
* **Unique models make the cache a net cost**: 426 allocations vs
  disabled's 414, plus 32 table constructions that are never reused — the
  cache adds bookkeeping to a zero-reuse stream.
* The artifact's accounted size is 17,472 bytes (1 KiB frequencies +
  16 KiB packed table + overhead) — the cache's peak byte bound scales
  linearly with distinct resident models.

### 2.2 Contention (O.16)

Cumulative timings for one 32-block decode (release):

| Mode | Workers | Lock wait | Build time | Single-flight wait | Lookup total |
|---|---|---|---|---|---|
| cold (1 model) | 1 | 0.9 µs | 51 µs | 0 | 70 µs |
| cold | 8 | 4.0 µs | 50 µs | 355 µs | 432 µs |
| cold | 16 | 86 µs | 54 µs | 960 µs | 1.14 ms |
| hot-set (16 models) | 1 | 1.3 µs | 868 µs | 0 | 893 µs |
| hot-set | 8 | 2.5 µs | 1.00 ms | 73 µs | 1.11 ms |
| hot-set | 32 | 28 µs | 1.55 ms | 90 µs | 1.72 ms |
| unique (32 models) | 1 | 1.8 µs | 1.85 ms | 0 | 1.88 ms |
| unique | 8 | 3.4 µs | 2.16 ms | 0 | 2.20 ms |
| unique | 32 | 4.1 µs | 3.61 ms | 0 | 3.66 ms |

Readings:

* **Build time is flat in worker count for a fixed model cardinality** —
  the construction runs outside the cache-state lock as designed (the
  single-flight requirement's payoff).
* **Lock wait is negligible through 8 workers** (single-digit µs) and
  remains a small fraction of lookup time at 16–32 workers (µs–ms scale
  vs ms-scale builds).  The global mutex is **not** a demonstrated
  serialization point for these workloads; a sharded design would add
  complexity without measured benefit (ADR-0016/0017).
* **Single-flight wait grows with workers for a same-key cold burst**:
  at 32 workers, 31 callers coalesce behind one build (355 µs–2.5 ms of
  condvar wait) — this is the designed deduplication working as intended,
  and it is why the cold mode performs exactly one build.
* The debug-build harness showed materially larger lock waits (up to 43 ms
  at 32 workers for unique) — a reminder that contention conclusions must
  be drawn from release measurements; the debug allocator and unoptimized
  critical sections exaggerate lock hold times.

### 2.3 Cold versus warm (O.14 bench)

Measured by the Criterion `model_cache` bench (every e2e case is
mode-proven before timing; the sealed numbers are in the
`RYG_RANS.PERF.CACHE.COLD_WARM` receipt):

| Mode pair | Small blocks (4–64 KiB) | Large blocks (1–4 MiB) |
|---|---|---|
| warm vs cold | warm is faster by the one-time artifact build (≈ 0.9 ms of table construction spread over bc blocks) | identical — the build cost is amortized to noise against decode time |
| warm vs disabled | warm saves the per-block construction entirely (≈ 50 µs × bc at 4 KiB) | identical |

The honest conclusion: **a warm cache materially improves small-block
decode** (the per-block packed-table construction is a large fraction of a
4 KiB decode), **is neutral for large blocks**, and **unique-model
streams make caching a net regression** (2.1).  The sealed receipt
quantifies these statements; the design does not force a positive
headline.

### 2.4 Thrash, hot-set, phase shift

* **Thrash (17 models, 16-slot cache)**: measured evictions == 1 at 18
  blocks and grows linearly with the number of blocks (exact at 1 worker;
  scheduler-dependent bounds at N workers — see the bench mode proofs).
  FIFO churn under a cycling working set is O(1) per access; the churn
  cost is one packed-table rebuild per evicted model.
* **Hot-set (16 models, 64-slot cache)**: zero evictions; 16 builds then
  all hits — the steady state a repeated-model workload should enjoy.
* **Phase shift** (soak rounds rotating hot sets): the FIFO cache
  re-acquires the returning set at one build per model (measured by the
  soak's builds counters); the re-acquisition cost is the same under FIFO
  and LRU because the shadow simulation shows both policies evict the
  same entries when the working set fits the capacity (ADR-0017).

### 2.5 Worker scaling

Decode throughput across 1/2/4/8/16/32 workers is measured by the e2e
bench for every mode × size; 32 workers is explicitly oversubscribed on
this 16-thread host and is labeled as such in the receipt.  The cache does
not change the scaling shape: the executor's reorder window
(`max_in_flight.max(workers) + workers`) and the cache's single-flight
coalescing keep the per-model build count at one regardless of worker
count (contention table above).

## 3. Honest limitations

* All numbers are for this host (Zen-family x86-64, 16 logical CPUs).
  The sealed receipts bind host metadata, so a different host's numbers
  are different measurements, not corrections.
* The allocation harness counts process-wide allocations; the reported
  deltas bracket one decode and the scaffolding cancels, but absolute
  numbers include allocator and runtime effects.
* Lock contention was measured on release builds with the `cache-timing`
  feature; the timing atomics themselves add a tiny per-lock cost (two
  relaxed atomic adds) that is part of the measured numbers.
* `unique` mode uses constructed distinct models (dominant-symbol data),
  not natural per-block histograms: natural uniqueness on public corpus
  data is measured separately by the `model_cache/public/natural` group
  (`RYG_RANS.PERF.CACHE.MIXED_PUBLIC`).

## 4. Workload classes and what each benchmark proves

| Class | Bench group | Proves |
|---|---|---|
| A disabled | `model_cache/e2e/disabled/*`, `model_cache/ops/disabled-bypass` | semantic baseline; construction cost baseline; zero retention |
| B/C cold / warm | `model_cache/e2e/cold/*`, `e2e/warm/*` | single-flight (1 build); hit-path speed; build-cost amortization |
| D hot-set | `model_cache/e2e/hot-set/*` | 16-model residency; 16 builds then all hits |
| E uniform mixed | (model cardinality spread via unique + public natural) | capacity transition, honest organic reuse |
| F thrash | `model_cache/e2e/thrash/*` | worst-case FIFO churn; byte accounting under eviction |
| G mixed sizes | every group × 6 block sizes | exact byte accounting across entry sizes |
| H phase shift | soak rounds (`synthetic-cache-soak` + `soak-public` rounds) | FIFO re-acquisition cost; deterministic cancellation round proves complete-or-Cancelled, never short Ok |
| I unique | `model_cache/e2e/unique/*` | cache overhead with zero reuse |
| J mixed public | `model_cache/public/*` + `stress-public`/`soak-public` | real corpus, natural + grouped modes, 1–32 workers, byte-exact source slices |

## 6. Execution families (post-v0.5.0 audit, MODEL_CACHE.WORKLOAD.2)

The repository distinguishes two workload families so that public-corpus
identity is never claimed for synthetic data:

* **`synthetic-cache-stress` / `synthetic-cache-soak`** (aliases `stress` /
  `soak`) — the cache-behaviour classes A–I on deterministic xorshift
  payloads with **constant seeds** (labeled `synthetic-cache-stress-v1`).
  These are the only place the cache access patterns of classes B/C/D/F/H
  can be forced precisely (one model, 65 models against 64 slots, ...);
  the payloads are *not* corpus-derived.
* **`stress-public` / `soak-public`** — the derived public schedule itself:
  every block resolves `source_id + source_sha256 + offset + length` to
  hash-verified extracted source bytes, encodes with the block's declared
  codec/scale, decodes, and asserts byte-exact output per window.  Natural
  mode measures organic reuse; grouped mode trains each group's model from
  the declared public training region and counts every fallback.  The
  schedules stream in bounded windows (window × block size ≤ 256 MiB), so
  `public-rans-mixed-16g` and `public-rans-stress-64g` execute without
  materializing the corpus.

A claim that a result "comes from the public corpus" is only true for the
second family (and the Criterion `model_cache/public` group); every
synthetic result is labeled as such (O.13 honesty).
